Especificación de Requisitos del Producto: Currículum Interactivo con IAVersión: 1.0Fecha: 23 de septiembre de 20251. Descripción General1.1 PropósitoEste documento describe los requisitos para el desarrollo de una aplicación web de portafolio personal llamada "Currículum Interactivo con IA". El propósito principal de esta aplicación es servir como una herramienta de presentación de candidatura dinámica e innovadora. A diferencia de un currículum estático, esta aplicación permitirá a los reclutadores y gerentes de contratación interactuar con un agente de IA (chatbot) para hacer preguntas en lenguaje natural sobre la experiencia, habilidades y proyectos del candidato, recibiendo respuestas instantáneas basadas en el contenido del currículum.1.2 Alcance del ProductoEl proyecto abarca el diseño, desarrollo y despliegue de una aplicación web completa que incluye:Una página de destino que muestra el currículum del candidato.Un agente de IA conversacional integrado, entrenado exclusivamente con los datos del currículum.Un backend para procesar las solicitudes de la IA y gestionar la lógica de negocio.Una interfaz de usuario (UI) de chat simple e intuitiva.1.3 Público ObjetivoReclutadores y Profesionales de Adquisición de Talento: Para una evaluación rápida y dirigida de la idoneidad del candidato.Gerentes de Contratación y Líderes Técnicos: Para profundizar en habilidades y experiencias específicas a través de preguntas directas.Entrevistadores Técnicos: Como una herramienta de conversación previa a la entrevista para familiarizarse con el perfil del candidato.2. Requisitos Funcionales2.1 Página Web del PortafolioFR-001: Visualización del Currículum: La página principal debe mostrar el currículum completo del candidato en un formato limpio, profesional y fácil de leer.FR-002: Descarga de Currículum: Debe haber un botón o enlace claramente visible que permita a los usuarios descargar una versión en PDF del currículum.FR-003: Diseño Responsivo: El sitio web debe ser totalmente responsivo, garantizando una experiencia de usuario óptima en dispositivos de escritorio, tabletas y móviles.2.2 Agente de IA Conversacional (Chatbot)FR-004: Interfaz de Chat: La aplicación debe presentar una interfaz de chat integrada, que incluya un campo de entrada de texto y un área de visualización del historial de la conversación.FR-005: Mensaje de Bienvenida: Al cargar la página, el agente de IA debe mostrar un mensaje de bienvenida proactivo y sugerir preguntas de ejemplo para guiar al usuario (p. ej., "Puedes preguntarme sobre su experiencia con Django" o "Háblame de sus proyectos de IA").FR-006: Procesamiento de Lenguaje Natural (PLN): El agente debe ser capaz de comprender preguntas formuladas en lenguaje natural sobre el contenido del currículum.FR-007: Generación de Respuestas Basada en RAG: Las respuestas del agente deben generarse utilizando un modelo de Generación Aumentada por Recuperación (RAG), basándose únicamente en la información contenida en el documento del currículum. Esto asegura que las respuestas sean precisas y relevantes para el perfil del candidato.FR-008: Memoria Conversacional: El agente debe mantener el contexto de la conversación actual, permitiendo a los usuarios hacer preguntas de seguimiento (p. ej., "Dime más sobre ese proyecto" o "¿Qué tecnologías usó allí?").FR-009: Manejo de Preguntas Fuera de Alcance: Si un usuario hace una pregunta cuya respuesta no se encuentra en el currículum, el agente debe responder cortésmente que su conocimiento se limita al documento y, si es posible, reorientar la conversación hacia temas relevantes.FR-010: Streaming de Respuestas: Para mejorar la experiencia del usuario, las respuestas del agente de IA deben aparecer en la interfaz de chat en tiempo real, palabra por palabra (streaming).3. Requisitos No Funcionales3.1 Pila TecnológicaRNF-001: Backend:Lenguaje: Python 3.9+Framework Web: Django (con Django REST Framework para la API).1Orquestación de IA: LangChain.Modelo de IA: API de Google Gemini (p. ej., gemini-2.5-flash).Base de Datos de Vectores: FAISS (para almacenamiento y búsqueda de embeddings).Servidor Asíncrono (Opcional): Celery con Redis para gestionar las llamadas a la API de IA si se anticipa una alta latencia.1RNF-002: Frontend:Framework: Streamlit (para una rápida creación de prototipos y una interfaz de chat funcional).Despliegue: La aplicación Streamlit se puede incrustar en un sitio web estático o dinámico mediante un iframe.RNF-003: Despliegue:La aplicación debe estar contenerizada usando Docker para facilitar el despliegue y la portabilidad.El despliegue se puede realizar en plataformas como Vercel, Heroku, o cualquier proveedor de IaaS/PaaS compatible.3.2 Seguridad y PrivacidadRNF-004: Sanitización de Datos: El documento del currículum utilizado como base de conocimiento para el agente de IA debe ser una versión sanitizada, sin información personal sensible como dirección completa, número de teléfono o correo electrónico personal.RNF-005: Gestión de Claves de API: Las claves de API (p. ej., Gemini API Key) deben gestionarse de forma segura utilizando variables de entorno y nunca deben ser codificadas en el código fuente.3.3 RendimientoRNF-006: Tiempo de Carga: El tiempo de carga inicial de la página web no debe superar los 3 segundos en una conexión de banda ancha estándar.RNF-007: Latencia de Respuesta del Chatbot: El tiempo desde que el usuario envía una pregunta hasta que comienza a recibir una respuesta (latencia de primer token) debe ser inferior a 2 segundos.4. Arquitectura del SistemaLa aplicación seguirá una arquitectura de Generación Aumentada por Recuperación (RAG).4.1 Flujo de Datos de Indexación (Offline)Carga del Documento: El sistema carga el documento del currículum sanitizado (formato PDF o Markdown).Fragmentación (Chunking): El documento se divide en fragmentos de texto más pequeños y manejables.Creación de Embeddings: Cada fragmento de texto se convierte en una representación vectorial numérica (embedding) utilizando un modelo de embeddings de la API de Gemini.Almacenamiento en Base de Datos de Vectores: Los embeddings se almacenan y se indexan en una base de datos de vectores FAISS, que se guarda en el disco para su uso posterior.4.2 Flujo de Datos de Consulta (Online)Entrada del Usuario: El usuario introduce una pregunta en la interfaz de chat de Streamlit.Llamada a la API: El frontend envía la pregunta del usuario al endpoint de la API de Django.Embedding de la Consulta: El backend crea un embedding para la pregunta del usuario utilizando el mismo modelo de embeddings.Búsqueda de Similitud: El sistema realiza una búsqueda de similitud en la base de datos de vectores FAISS para encontrar los fragmentos de texto del currículum más relevantes para la pregunta.Construcción del Prompt: Se construye un prompt para el modelo de lenguaje grande (LLM) que incluye la pregunta original del usuario y los fragmentos de texto recuperados como contexto.Generación de Respuesta: El prompt se envía al modelo de chat de Gemini, que genera una respuesta basada en el contexto proporcionado.Devolución de la Respuesta: La respuesta generada se devuelve al frontend a través de la API y se muestra al usuario en la interfaz de chat.5.
